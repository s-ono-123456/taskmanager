# 論点: 週次サイクル（Cycles）のデータ表現

- 起票: 2026-09-13 / Linear風Cycles機能導入の一部（`docs/design/data-model.md` 参照）
- 論点: 「今週やること」「バックログ」という週次の区分を、DB上でどう表現するか。
- 状態: **案2採用・実装完了（2026-09-13）**

## 背景

ユーザーから、個人タスク・JIRA連携タスクの両方を対象に、週次の区切りで「今週やること」
「バックログ」「今週の完了実績」を可視化したいという要望があった。grillingスキルでの
確認により、過去の週（サイクル）ごとの実績を後から振り返る必要は無く、「今のサイクルだけ
見えればよい」という回答を得ている。

## 方針案

| 案 | 内容 | コスト | リスク | 状態 |
|---|---|---|---|---|
| 案1 | 独立`cycles`テーブルを持ち、`tasks.cycle_id`でFK参照する（Linear本家に近い方式） | 中（テーブル設計・マイグレーション・履歴クエリが増える） | 「過去サイクルの履歴参照は不要」という要件に対して過剰設計になる | 不採用 |
| 案2 | `tasks.cycle_start_date`（所属週の月曜日、nullable）列のみで表現する。NULL=バックログ、値あり=その週の「今週」 | 低（既存の`due_date`列追加と同じマイグレーションパターンで済む） | 過去の週ごとの履歴一覧は取得できない（要件外なので問題なし） | **採用** |

## 採用理由 / 検討経緯

「過去サイクルの履歴参照は不要」という確定要件に対し、独立テーブル化（案1）は機能に対して
コストが見合わない過剰設計と判断した。`tasks.cycle_start_date`のみで表現する案2を採用し、
既存の`due_date`列追加時と同じ`columnExists`+`ALTER TABLE`のマイグレーションパターンを
再利用する。週境界での自動繰り越しは、この列の値を書き換えるだけで実現できる
（`docs/adr/complete/cycle-rollover-execution.md`参照）。
